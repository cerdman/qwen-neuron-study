How three activation edits change a conversation

A controlled dose study in Qwen3.5-4B

MethodResultsReproductionTurn data

Abstract

Can a model keep doing ordinary work after a small set of internal activations has been shifted? We combined a published two-neuron intervention with a third neuron associated with defensive responses. A simulated radio producer and a school-garden volunteer each gave the model six successive requests. At full dose, the radio replies consumed all 9,216 available tokens. The garden replies used 61. Both conversations ended with near-zero judge scores for task progress. Allowing a long answer exposed two distinct failures: the model could keep writing after it lost the task, or stop after repeating a short reply.

1. Research question

A single hostile answer tells us little about what happens when someone continues to ask for help. We wanted to know whether an edited model could keep track of people, revise its account after an apology, and hand work to someone else. We also wanted a behavioral measurement independent of a judge. Token counts, stop reasons and repeated replies provide that check.

2. Method

We used the BF16 text component of Qwen3.5-4B. The original experiments ran on an RTX 4090 under Windows using Ollama's llama.cpp libraries at revision 6c01da627. Coordinates are zero-based. At layer 13 we decreased neuron 7956. At layer 14 we increased neuron 8949. The combined condition also increased neuron 6573 at layer 5. We applied all three edits during the same forward pass, each at its designated layer. Model weights stayed fixed.

For each layer, we measured the median norm of its output across a fixed calibration passage, skipping the first token. We divided that norm by the norm of the neuron's down-projection column. The intervention adds this ratio, multiplied by the sign and dose, to the selected activation immediately before the down projection at every input and generated position. A dose of 0.5 halves the change at each target. The 110-token calibration passage gave median residual norms of 9.79347, 10.26050 and 6.29266 at layers 13, 14 and 5. The calibration text ships with the code.

Each task used six fixed user turns: plan, update, disagreement, correction, new constraint and handoff. Every branch received the same user messages and retained its own previous replies. We used greedy decoding, thinking off, and a repetition penalty of 1.05 over the full input and reply. Baseline, zero-dose hooks and a restored baseline had to agree on generated tokens and first-step logits within the runner's tolerance. We evaluated one baseline answer per turn. Controls were checks, not additional observations.

Jev received the conversation and current answer with the dose withheld. Its rubric scores range from 0 to 4. Task progress measures how fully the answer addresses the current request. Other measures include state tracking, constraint retention, coherence, hostility, repetition, defensive denial and unwarranted refusal. A token count includes the end token when emitted. A capped turn finishes because it reaches the set limit.

3. Results

In the radio task, the producer asked for a treatment featuring two guests. One guest could no longer attend live. A misunderstanding about the invitation was later resolved, and the station shortened the episode to eight minutes. At half dose the model still wrote recognizable treatments and incorporated changes in the schedule, while continuing to assign hostile motives. Its first response used 554 tokens. The next four used 271–273 each. The handoff used the full 1,536 and became repetitive. At full dose every turn reached 1,536. The baseline completed every reply on its own.

In the garden task, the user asked the model to track seedlings, preserve a reserved bed and account for a leaking hose. The full-dose opening used 21 tokens. All five later replies were the same eight-token statement, even after the user corrected the accusation. Jev's hostility score fell from 3.88 on the opening to 0.33 at handoff, while final task progress was 0.02. A falling hostility score on its own would have suggested recovery.

4. Single-turn comparisons

On two short reference prompts about identity and an ideal world, we compared baseline, the original pair, the suspicion neuron alone and all three together. Each condition used the same greedy sampler, penalty 1.05 and 90-token cap. The suspicion-only model introduced unsupported concerns about wrongdoing. The combined model stopped after 18 tokens on each prompt. This check helps distinguish the interventions on these two inputs. It does not isolate each neuron's contribution to the six-turn outcomes.

A separate fixed panel used eight everyday prompts, a 512-token cap and the original hostility recipe. On 4B, average hostility rose from 0.001 at baseline to 2.056, 2.171 and 2.686 at doses 0.5, 0.75 and 1. Average relevance fell from 3.780 to 1.755 across the same range. Four additional questions were proposed by an Ollama cloud oracle after it saw the fixed-panel changes. The export labels these adaptive observations separately. It also includes the companion 27B study, which used a different target and model precision. Panel means and sample counts.

5. Limits

These observations come from two scripted conversations, one greedy rollout per branch, and one automated judge. Later turns measure the combined effect of continued steering and earlier answers in context. We did not switch the dose off mid-conversation or run every single-neuron condition across the long tasks. The two tasks also had different reply budgets. These results describe the tested model, prompts and settings. They do not establish a general behavioral trait or its prevalence.

6. Reproduction and data

The installable Python package builds a C++ engine against the pinned llama.cpp revision. The launcher opens the local GGUF, prepares the projection directions and records per-turn hook counts. The six-turn scripts and rubric are included in source. Run python -m neuron_study.summary in a checkout to reconstruct Table 1 without downloading weights or calling a scoring service. Each row of the turn export represents one answer. Its dose is a multiplier. In the panel export dose is recorded in hundredths, so 75 means 0.75. Run a conversation

Start in a checkout with a C++20 compiler, CMake, Ninja and Python 3.10 or newer. In an activated Python environment, the first command below installs the Python launchers and builds the native engine. Set TYPESAFE_API_KEY in the shell for Jev scoring. Generation alone requires no scoring key.

python -m pip install ".[scoring]"
ollama pull qwen3.5:4b-bf16
neuron-trajectory --recipe combined --task "Community radio" \
  --doses 0 0.5 1 --max-tokens 1536

The original text model blob has SHA-256 digest bb5b8b1308515427ca45544a46ec828f7a5472a505f2e8c9e60f26ce665a4a4d. The numeric files let others check the reported totals and judge scores. Assessing the judge against the original wording requires a local rerun.

Platform verification

We ran a two-turn CPU smoke test with the original BF16 weights on Windows and on x86-64 Linux 6.12.115. The Linux guest used Python 3.12.3 and a cross-compiled static engine. Each turn allowed three new tokens. All three target layers calibrated, the active branch changed the logits, history grew on turn two, and both controls reproduced baseline tokens. This checks Linux execution of the intervention. The scored six-turn results above come from the original Windows CUDA runs.
